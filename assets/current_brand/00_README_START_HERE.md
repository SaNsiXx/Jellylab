# Jelly Labs — Claude Website Pack

Ten pakiet jest kompletnym punktem startowym do zbudowania strony Jelly Labs przy pomocy Claude/Claude Code.

## Kolejność użycia

1. Przekaż Claude cały folder.
2. Wklej zawartość `02_CLAUDE_MASTER_PROMPT.md`.
3. Dodaj materiały z folderu `assets/current_brand`.
4. Poproś Claude najpierw o wygenerowanie mapy plików i działającego prototypu strony głównej.
5. Po akceptacji hero i nawigacji zleć budowę pozostałych podstron.
6. Przed publikacją uzupełnij wszystkie pola oznaczone `[DO UZUPEŁNIENIA]`.

## Zawartość

- `01_MASTER_WEBSITE_BRIEF_PL.md` — strategia, architektura, UX, menu, animacje, funkcje i wymagania.
- `02_CLAUDE_MASTER_PROMPT.md` — gotowy prompt do wklejenia do Claude.
- `03_SITE_COPY_EN.md` — komplet tekstów angielskiej wersji strony.
- `04_SITE_COPY_PL.md` — komplet tekstów polskiej wersji strony.
- `05_FORMS_LEGAL_CRM.md` — formularze, zgody, double opt-in, Jelly Box i integracja CRM.
- `06_ASSET_MANIFEST.md` — lista grafik oraz instrukcje ich wykorzystania.
- `07_DESIGN_TOKENS.json` — kolory, typografia, promienie, cienie i ruch.
- `08_CMS_CONTENT_MODEL.json` — struktura danych dla talentów, artykułów, case studies i zespołu.
- `assets/current_brand` — obecne logo, banner i trzy kreacje kampanii Jelly List.
- `assets/concepts/JellyLabs_Hero_Concept.svg` — referencja wizualna hero.

## Najważniejsza decyzja strategiczna

Strona ma prowadzić dwa typy odbiorców, ale główny lejek jest sprzedażowy:

1. Klient B2B → **Get the Jelly Drop** → formularz → double opt-in → lista dostępnych specjalistów → kontakt handlowy.
2. Developer → **Join the Jelly Crew** → formularz kandydata → kwalifikacja → bench.

Nie należy mieszać tych dwóch formularzy ani ich komunikacji.

## Zasada marki

**Bold outside. Reliable inside.**

Jelly może mówić odważnie, ale dowozi po partnersku. Strona nie może wyglądać jak kolejny generyczny software house ani jak sklep ze słodyczami.
